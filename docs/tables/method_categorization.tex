    \vspace{0.5em}
    \begin{flushleft}
    \scriptsize
    $^{\ast}$~The \texttt{mse} sweep entry dispatches to $\mathrm{BCE}$,
    $\mathrm{CE}$, or $\mathrm{MAE}$ when the problem's two-stage loss so
    indicates; all four are prediction-loss baselines and share this row.\\[2pt]
    $^{\dagger}$~\textbf{Every row in this table is also decision-aware
    via the finite grid search over $(\mathrm{lr},\,\mathrm{bs})$ whose
    winner is picked by decision regret.} This gives even a
    nominally ``blind'' baseline (MSE) a constrained form of
    decision-aware model selection; see \citet{elmachtoub2025misspec}
    for a well-specified-regime analysis.  Within each run the best
    epoch's checkpoint is selected by \emph{validation} decision regret;
    in the current sweep, however, the across-config
    $(\mathrm{lr},\,\mathrm{bs})$ winner is picked by \emph{test}
    decision regret (leakage through HP selection; planned fix
    documented in the dissertation's reproducibility appendix).\\[2pt]
    $^{\ddagger}$~PG is defined for all problems except
    \texttt{shortestpath} (warcraft); the finite-difference direction $c$
    and detached-solver pattern support both linear and non-linear
    objectives (e.g.\ the sub-modular objective of \texttt{budgetalloc}).\\[2pt]
    \textit{Solves / batch} counts CO-solver invocations per mini-batch
    element per forward--backward pass; $n$ is the Phase-2 Monte-Carlo
    sample count.  \textit{\#\,HP} counts hyper-parameters the benchmark
    treats as tunable: always $\mathrm{lr}$ and $\mathrm{bs}$, plus any
    method-specific HPs swept in Phase~2.
    \end{flushleft}
